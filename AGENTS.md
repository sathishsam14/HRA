# HRA project rules (read before every task)
- JavaScript only (no TypeScript). Next.js App Router. No src folder. Tailwind.
- Database: PostgreSQL through Prisma. Never delete rows (use an active flag). AuditLog is append-only.
- Five screens only: Login, Dashboard, Rating Engine, MIS Report, Audit Trail.
- Roles: Admin, Handicapper, Viewer. Viewer is read-only, enforced on the server, not only in the UI.
- Ratings are calculated automatically. There is no Generate button.
- The Handicapper keeps the recommendation or overrides it. An override needs: final change, reason, user, time. Every override goes to the Audit Trail.
- Rating logic lives only in lib/rating-engine. Never rewrite it. All rule values are in lib/rating-engine/config.js.
- Source of truth: docs/BRD-BTC-HRA_Application.pdf. If documents conflict, the BRD wins.
- Once they exist, read docs/DATA_FORMATS.md and docs/RULES_SUMMARY.md before every task.
- An unrated horse is null in the database, never -999.
- Starter, Veterinary and Incident reports are optional. Use them when uploaded; rate without them when not. Optional columns are used for rating only when present.
- Mandatory race data: Venue, Race Date, Race Category, Race No, Distance, Horse Name, Placing, Current Rating, Number of Previous Runs. Everything else may be blank.
- Secrets only in .env, never in code.
- No Docker. Local database is Postgres.app. Production is Postgres installed on the server, run with PM2.
- Do one step at a time, run the tests, then stop and report.
